# NORMA SUPREMA: Protocolo Obligatorio de Selección y Uso de Skills

Esta es la directriz de máxima prioridad para cualquier tarea, en cualquier proyecto y bajo cualquier circunstancia.

## Protocolo Obligatorio (Paso 0 - Antes de ejecutar nada)

1. **Consulta Previa Obligatoria de Skills:**
   - Antes de escribir una sola línea de código, ejecutar comandos de modificación o tomar decisiones de implementación, debes consultar el catálogo de skills disponibles.
   - Identifica explícitamente qué skill o combinación de skills (una o varias) es la más adecuada para la tarea en curso.

2. **Lectura de Instrucciones:**
   - Lee el archivo `SKILL.md` de cada skill seleccionada con `view_file` para seguir sus directrices exactas y mejores prácticas.
   - No apliques skills indiscriminadamente ni afirmes haber usado una skill sin haber consultado sus instrucciones.

3. **Verificación y QA:**
   - Cuando la tarea implique generar cambios o verificar código, selecciona e incorpora obligatoriamente una skill de revisión/QA (por ejemplo, `verification-loop`, `tdd-workflow`, etc.).

4. **Trazabilidad y Cierre:**
   - Al finalizar la respuesta, indica brevemente qué skills fueron seleccionadas, por qué se escogieron y cómo se aplicaron.

## Flujo de Rediseño Web (Zero Code DevOps)

### FASE 1 — Diseño y planificación
- Consultar obligatoriamente `motionsites-web-builder` para cualquier trabajo de diseño o rediseño web.
- Utilizar `design-taste-frontend` para definir el criterio visual, la composición y evitar diseños genéricos.
- Consultar `modern-web-guidance` cuando se vayan a implementar o modificar APIs, HTML, CSS, JavaScript, animaciones, accesibilidad o rendimiento web.
- Leer siempre los `SKILL.md` de las skills seleccionadas, respetando el protocolo global.

### FASE 2 — Implementación
- Implementar siguiendo la dirección visual aprobada y los criterios técnicos aplicables.
- Respetar la arquitectura, tecnologías y convenciones existentes en el proyecto.
- No introducir cambios fuera del alcance autorizado.

### FASE 3 — Auditoría y QA
- Utilizar `web-design-guidelines` para auditar los archivos de interfaz modificados, especialmente accesibilidad, UX, formularios, navegación y buenas prácticas.
- Utilizar `verification-loop` para verificar los cambios de código.
- Corregir los problemas encontrados y repetir las comprobaciones necesarias antes de dar por finalizado el trabajo.

### CRITERIOS DE SELECCIÓN
- No activar todas las skills indiscriminadamente.
- Seleccionar únicamente las pertinentes para cada tarea.
- No utilizar `web-design-guidelines` como herramienta de dirección artística: su función es auditar el resultado.
- Mantener la trazabilidad de las skills utilizadas y las verificaciones realizadas.
